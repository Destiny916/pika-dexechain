# Pika Docker 迁移到新机器 —— 入口清单

> 目标:把跑通的 Pika 采集环境搬到新机器。迁移分**两条轨**,各有一个脚本:
>
> | 轨 | 脚本 | 性质 | 何时跑 |
> |---|---|---|---|
> | 🖥️ **软件轨** | `migrate_software.sh` | PIKA 采集离线确定性；DexEChain 工具容器按配置拉取/复用 | 拿到迁移包就能跑 |
> | 🔌 **硬件轨** | `setup_hardware.sh` | 物理相关、**引导式**(边插边认) | 设备接上新机器后 |
>
> **核心认知**:软件轨每台机器结果一样,所以能一键;硬件轨(USB 端口、左右手、基站位置)
> **换机器一定会变**,只能引导式做。其中**基站校准每换一次场地都必须重来**。

---

## 0. 迁移包内容(整个 `pika-migrate/` 拷到新机器)

```
pika-migrate/
├── pika-image.tar.gz        # 镜像(docker save pika:humble,~1.5G)
├── pika-project.tar.gz      # 项目目录(pika_ros/install/配置,~1.1G)
├── dexe-sensors_0.4.3+20260630104156+a5b1db7_amd64.deb  # KFCv2 网络头相机 ROS2 节点(可选后端)
├── pika_migrate.conf        # 迁移前配置:用户/路径/ROS_DOMAIN_ID/头相机后端
├── migrate_software.sh      # 🖥️ 软件轨一键脚本
├── start_dexechain_tools.sh # DexEChain HDF5/UniVis 处理容器启动脚本
├── setup_hardware.sh        # 🔌 硬件轨引导脚本
└── documents/               # 三份文档(本文件 + 部署教程 + 采集SOP)
```

U 盘 / scp / 局域网拷过去均可(约 2.5G)。若启用 DexEChain 工具容器，新机器还需要能访问
`pika_migrate.conf` 中配置的镜像仓库和 EmbodiChain git 仓库；已有镜像/仓库时会复用。

## 1. 迁移前先改配置(新机器第一步)

先编辑迁移包根目录的 `pika_migrate.conf`。后续 `migrate_software.sh` 会在**任何安装动作前**读取它,并在项目根生成运行时配置 `pika_runtime.env`。

常用项:
```bash
PIKA_USER="${PIKA_USER:-agilex}"          # 目标机器实际用户名;旧环境可写 dex
HOST_HOME="${HOST_HOME:-/home/${PIKA_USER}}"
APP_DIR="${APP_DIR:-${HOST_HOME}/app}"
PIKA_DIR="${PIKA_DIR:-${APP_DIR}/pika}"
AGILEX_DIR="${AGILEX_DIR:-${HOST_HOME}/agilex}"
DATA_DIR="${DATA_DIR:-${AGILEX_DIR}/data}"

HEAD_CAMERA_DRIVER="${HEAD_CAMERA_DRIVER:-orbbec}"   # orbbec | kfcv2 | none
HEAD_CAMERA_IP="${HEAD_CAMERA_IP:-192.168.20.30}"
HEAD_CAMERA_EYE="${HEAD_CAMERA_EYE:-left}"
CAPTURE_HZ="${CAPTURE_HZ:-}"              # 留空自动:orbbec=20,kfcv2=10

# KFCv2 每次采集前画面对齐；动态使用目录下创建时间最新的 JPEG
KFC_ALIGN_BEFORE_CAPTURE="${KFC_ALIGN_BEFORE_CAPTURE:-true}"
KFC_ALIGN_REFERENCE_DIR="${KFC_ALIGN_REFERENCE_DIR:-${AGILEX_DIR}/kfc_reference}"

ENABLE_DEXECHAIN_TOOLS="${ENABLE_DEXECHAIN_TOOLS:-true}"
START_UNIVIS_AFTER_MIGRATE="${START_UNIVIS_AFTER_MIGRATE:-false}"
DEXECHAIN_CONTAINER_NAME="${DEXECHAIN_CONTAINER_NAME:-dexechain-tools}"
DEXECHAIN_WORKSPACE="${DEXECHAIN_WORKSPACE:-${HOST_HOME}/workspace}"
EMBODICHAIN_DIR="${EMBODICHAIN_DIR:-${DEXECHAIN_WORKSPACE}/embodichain}"
EMBODICHAIN_BRANCH="${EMBODICHAIN_BRANCH:-wjf/workflow_enh}"
DEXECHAIN_USE_GPU="${DEXECHAIN_USE_GPU:-auto}"      # auto | true | false
DEXECHAIN_PYTHON="${DEXECHAIN_PYTHON:-/opt/miniconda/envs/py310/bin/python}"
DEXECHAIN_BOOTSTRAP_PACKAGES="${DEXECHAIN_BOOTSTRAP_PACKAGES:-python-multipart>=0.0.12}"
UNIVIS_PORT="${UNIVIS_PORT:-8010}"
HDF5_WORKFLOW_DIR="${HDF5_WORKFLOW_DIR:-${AGILEX_DIR}/hdf5_workflow}"
RAW2HDF5_BASE_CONFIG="${RAW2HDF5_BASE_CONFIG:-precheck_raw_to_hdf5}"
```

> 旧文档里的 `/home/dex/...` 不再是硬要求。软件轨会按配置把项目文本里的默认路径从 `/home/dex` 替换为 `HOST_HOME`。

> `pika-migrate` 是 EmbodiChain workflow 的数采侧使用者，只负责安装/启动容器和填本次
> `inputs`、`output_dir`。workflow 阈值、预检放行策略、相机格式处理和数据修复逻辑应在
> EmbodiChain 仓库维护。发现缺陷时，用“场景 + raw 数据现象 + workflow 报告/错误”反馈到
> EmbodiChain 侧修复，不在 `pika-migrate` 里无条件堆兼容。

## 2. 前置(新机器一次性,需联网/sudo)

软件脚本**只检测不自动装**这两样,缺了它会报错并给安装提示:

```bash
# Docker(若没有)
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER          # 之后重新登录,docker 免 sudo

# NVIDIA 容器运行时(docker_run.sh 用了 --gpus all,必须有)
#   参考 NVIDIA Container Toolkit 官方指南安装后:
sudo nvidia-ctk runtime configure --runtime=docker && sudo systemctl restart docker
```

> ⚠️ 路径由 `pika_migrate.conf` 决定。新机器用户名不是 `dex` 时,先把 `PIKA_USER`/路径改成实际值再跑软件轨。

## 3. 🖥️ 软件轨 —— 一键

```bash
cd /path/to/pika-migrate
bash migrate_software.sh
```

无参数模式面向空白环境。如果检测到已有 PIKA 项目、容器或镜像，脚本会明确推荐
`--reinstall` 并默认停止；只有明确输入 `y` 才会继续复用旧环境。非交互运行遇到已有环境会直接停止。

如果已有环境不完整或需要从迁移包彻底重建软件环境：

```bash
bash migrate_software.sh --reinstall
```

`--reinstall` 会先显示实际目标并要求输入 `REINSTALL` 确认，然后删除 PIKA 容器、
DexEChain 工具容器、PIKA 项目目录、PIKA 镜像和已安装的 `dexe-sensors`，再继续全新安装。
它**不会备份被删除的项目配置/校准**，但会明确保留整个 `${AGILEX_DIR}`（采集数据、HDF5、
输出和日志）、`${EMBODICHAIN_DIR}` 仓库、DexEChain 基础镜像、迁移包和硬件 udev 规则。

它依次做(**幂等,可重复跑**,每步打印 ✅/❌):

1. 前置体检(docker / nvidia / 磁盘 / 包是否在)
2. `docker load` 镜像(已有则跳过)
3. 解压项目到 `${APP_DIR}`(已有则不覆盖)
4. 建数据目录 `${DATA_DIR}`(采集时按任务再分子目录 `data/<任务名>/`,启动 `start_collect.sh` 会让你选/建任务,详见采集 SOP)
5. 安装/校验 KFCv2 头相机 deb 到 `/opt/dexe_sensors`(若迁移包内有 deb;Orbbec 不依赖它)
6. 跑 `docker_run.sh` 起持久容器 `pika`(`/opt/dexe_sensors` 会挂进容器)
7. 进容器补 `.bashrc`(source / `LD_LIBRARY_PATH` / 左右手 code)+ libsurvive 持久化软链
8. 验证 `ros2 pkg list | grep pika_locator`,并尽量验证 `ros2 pkg executables kfcv2`
9. 若 `ENABLE_DEXECHAIN_TOOLS=true`，启动 DexEChain 处理容器 `dexechain-tools`

跑完看到「软件轨迁移完成 🎉」即成功,此时有两个职责分离的容器：

| 容器 | 职责 | 日常入口 |
|---|---|---|
| `pika` | PIKA raw 采集、设备栈、ROS2 topic | `bash /home/dex/app/pika/pika_ros/scripts/start_collect.sh` |
| `dexechain-tools` | UMI HDF5 workflow、UniVis、后续 raw precheck | `bash start_dexechain_tools.sh ...` |

DexEChain 工具容器来自 `/home/dex/setup_inference.sh` 中的 W1 inference 镜像：

```bash
# x86_64
192.168.3.13:5000/w1_act:embodichain-20260715-8f82de52

# aarch64
192.168.3.13:5000/w1_act:embodichain-20260706-fffe080c
```

它不会启动 inference manager/client 服务，只作为常驻工具容器运行，并挂载：

```text
${DEXECHAIN_WORKSPACE} -> /root/workspace
${AGILEX_DIR}          -> ${AGILEX_DIR}
```

常用命令：

```bash
cd /path/to/pika-migrate

# 启动/复用 DexEChain 处理容器
bash start_dexechain_tools.sh start

# 启动 UniVis，默认 http://127.0.0.1:8010
bash start_dexechain_tools.sh univis

# 一键 raw_checker + raw_to_hdf5。调用 EmbodiChain run_workflow.sh；
# head_camera_format 根据 HEAD_CAMERA_DRIVER 自动映射。
bash start_dexechain_tools.sh raw2hdf5 /home/dex/agilex/data/<任务名>
bash start_dexechain_tools.sh raw2hdf5 /home/dex/agilex/data/<任务名>/episode10

# 默认输出目录：
# /home/dex/agilex/hdf5_workflow/<任务名>_YYYYMMDD_HHMMSS
# /home/dex/agilex/hdf5_workflow/<任务名>_episode10_YYYYMMDD_HHMMSS
#
# 上传/UniVis 使用真实 HDF5 目录：
# <output_dir>/<任务名>

# 运行 UMI workflow
bash start_dexechain_tools.sh workflow /home/dex/agilex/hdf5_workflow/<任务名>/umi_workflow.yaml

# 进入容器排查
bash start_dexechain_tools.sh shell
```

> 🔧 **换了 Sense 硬件**:**不用手抄序列号**。LHR 跟设备走、不跟机器——同一批大头搬机这两个值不变;
> 真换了大头,从硬件轨 ② 开始:② 自动探测在线 LHR 写进 `.bashrc`,③ 完成基站校准,
> 最后 ④ 挥手核对左右、反了一键对调。
> (顶部 `PIKA_L_CODE/PIKA_R_CODE` 只是同设备搬机的恢复默认值。)

## 4. 🔌 硬件轨 —— 引导式(设备接上后)

```bash
bash setup_hardware.sh        # 菜单式,每项可单独选/跳过;udev 操作会要 sudo
```

| 菜单项 | 做什么 | 关键 |
|---|---|---|
| ① 基站定位 udev | 装 `81-vive.rules` | —— |
| ② 按手柄绑定(夹爪 USB + D405 + LHR) | **一次插一只手柄**(整根 USB3 线),脚本 diff 同时定夹爪端口(50=左/51=右)+ D405 序列号；wireless 模式随后探测两个 LHR 并立即写入 `.bashrc` | LHR 探测需 start_multi_sensor 没在跑；必须恰好读到两只，否则本步骤失败 |
| ③ 基站校准引导 | 检查前提 + `survive-cli --force-calibrate`(可选自动起) | 每换场地必做;每台 acc err < 0.005；必须先校准再启动定位节点核对左右 |
| ④ 左右手核对 | `rqt_image_view` 挥手定物理左右；同步采样两路 `PoseStamped` 的平移/旋转变化，依次测静止、只动左手、只动右手 | 不再用 topic Hz 猜左右；明确反向时可对调 LHR、重启并自动复测；正常结束/报错/Ctrl+C 都会清理本步骤节点 |

**② 的插拔引导流程**(替代了文档里手动「查端口→改文件」那段最易错的活):
拔光两只 →(空白基线)插左手(整根 USB3 线,回车;记夹爪端口=50 + 该手 D405 序列号)→
再拔光 →(空白基线)插右手(回车,记=51 + 另一台 D405)→ 写 udev 规则 + 把两台 D405 序列号写进
`start_multi_sensor.bash` → **最后提示把两只都插上,再验证** `ttyUSB50/51`、`video50/51` 四个软链；
wireless 模式继续探测两只 LHR 并写入容器 `.bashrc`。
> 为何每只都要先拔光建空白基线:拔左插右时,右鱼眼可能抢占左刚释放的同一个 `/dev/videoN`(设备号复用),
> 若基线里还留着左手,集合差会漏检右鱼眼 → video 规则写空。空白基线杜绝此坑;鱼眼没解析全会报错、不写半截规则。

**② 的自动抓 LHR**:在 start_multi_sensor **没在跑**时,脚本编译跑 `lhr_probe`(读 `survive_simple_serial_number`,
config 一到就有、不需校准)抓在线两个 LHR——与 `.bashrc` 一致则保留当前左右顺序,不同(换了大头)
则先写入暂定顺序。随后先跑 ③ 校准，再由 ④ 挥手核对左右。

> 详细查端口 / rqt 挥手复核左右,见 `PIKA_采集SOP.md` 附录 A/B。

## 速查:换机器一定会变、要重做的四件事

1. **宿主机 docker / nvidia / 代理** —— 第 1 步装好(脚本只检测不代装)。
2. **USB 端口绑定** —— 新机端口号必变 → `setup_hardware.sh` ② 插拔重认。**多设备别挤一个 USB hub**(集体掉线的根因)。
3. **PIKA 容器 `.bashrc`** —— `docker_run.sh` 重建容器会丢 → `migrate_software.sh` ⑥ 自动补(幂等)。
4. **基站校准** —— 物理相关,**每换场地必 `--force-calibrate`**。

## 速查:高频坑

- 🟢 **定位标签没开绿灯** → `survive-cli` 卡在 `clearing position`。先长按夹爪顶部大头到绿灯。
  (注:本套走 watchman dongle,dongle serial 永远是裸的、不会变 `LHR-xxxx`;判大头在线看 `survive-cli` 的 `LightcapMode→2`/解算,**别看 `/sys` serial**。)
- 🔌 **多设备挤一个 USB hub** → 定位/相机集体掉线。两夹爪、两台 D405 分到不同 USB 控制器。
- 🔄 **重启电脑后用 `docker start pika`**,**别用 `docker_run.sh`**(那是重建会丢配置)。
- 🌐 **多机环境 topic 串扰** → `docker_run.sh` 已设 `ROS_DOMAIN_ID=42` 隔离,避免和局域网其他 ROS2 机器(如 Piper/Orbbec)的 `/camera_l` 等 topic 撞车污染采集。多台 pika 同网采集时各设不同 domain。
- 🖱️ **采集结束**:先**双击夹爪停录**(存盘)→ 再 **Ctrl+C** 结束采集节点 → PikaCapture 窗口 3 秒自动关。顺序别反(先双击停、后 Ctrl+C);别用 Ctrl+C 去停**正在录**的(会存成残缺被自动删)。

## 附 A:本包已固化的坑修复(从零迁移实测踩出来的)

新机器开箱即用,以下坑已在本包修掉、**不会再遇到**:

| 坑 | 修复(已固化进包) |
|---|---|
| numpy 2.x → cv_bridge 崩(鱼眼采集挂 `_ARRAY_API not found`) | 镜像已 baked **numpy 1.26.4**;Dockerfile 钉 `numpy<2`(opencv 不必钉,pip 自选 4.13 共存) |
| 容器缺 xterm → 采集报 `FileNotFoundError: xterm` | 镜像已 baked **xterm** |
| 局域网多 ROS2 机器(如 Piper/Orbbec)topic 串扰污染采集 | `docker_run.sh` 加 **`ROS_DOMAIN_ID=42`** 隔离 |
| 夹爪 + D405 要分两次插拔 | `setup_hardware.sh` ②③ 合并为**按手柄一次插拔**,左右天然一致 |
| 拿 `/sys` serial 找 `LHR` 判大头在线(本套 dongle serial 永远是裸的) | 改为看 `survive-cli`(WM0/WM1 + LightcapMode→2/解算)或 get_code(rviz LHR) |
| Ctrl+C 结束采集 → 漏记统计、报 `exit code 2` | `run_pika.sh` 启动 **rebuild_stats** 按 episode 目录补全;同号重录去重。正确收尾:双击停录 → Ctrl+C → 窗口 3 秒自动关 |
| `bash -lc` 不读 `.bashrc` → 验证误报找不到包 | `migrate_software.sh` 验证改为自己 `source`(不靠登录 shell) |
| 容器以 root 跑 → 采集数据宿主侧属 root、宿主用户删不动/改不动(被"锁") | `run_pika.sh` 采完自动 `chown` 回宿主用户(属主从数据根目录自动推断,无需配置)。早期遗留 root 数据:宿主侧 `sudo chown -R dex:dex /home/dex/agilex/data` 一次性解锁 |
